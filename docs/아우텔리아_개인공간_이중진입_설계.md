# 아우텔리아 '나만의 공간' 이중 진입 설계

2026-11-19 사용자 결정에 따른 변경. **포르투 노바의 주인공 방도, 독립된 농장형 두 번째 RPG도 아님.**

## 확정 원칙
- **나만의 공간은 독립 기능**으로 제공한다.
- 온앤오프 플랫폼(#space-autelia)에서 RPG를 플레이하지 않고도 이용한다.
- 아우텔리아 RPG를 플레이하는 중에도 메뉴 → 나만의 공간에서 이용한다.
- 같은 계정·같은 캐릭터 슬롯은 두 입장에서 **동일한 갤러리 데이터**를 사용한다. 방문 토큰·장식·미션 기록의 중복 저장을 막는다.
- 전투 스탯과 현실 성장 보상은 분리한다. 기존 훈련 포인트/배분 스탯은 구 저장 호환을 위해 보존한다.
- 출석은 하루 한 번 소액 꾸미기 보상, 연속 출석이 끊겨도 초기화나 불이익이 없다.
- 별도 캐릭터별 기록이다. 계정의 여러 캐릭터가 단일 갤러리를 공유하지 않는다(추후 변경 시 명시적으로 결정).

## 구현 경로
1. **온앤오프 플랫폼**: 로그인 후 상단 '나만의 공간' 또는 마이페이지 '나만의 공간 열기' → `#space-autelia`.
2. **플랫폼 독립 보기**: 게임 iframe을 `games/autelia/index.html?space=1` 로 열되, 전투·이동 게임 루프는 시작하지 않는다. 즉시 기존 갤러리 UI를 연다.
3. **RPG 안**: 기존 메뉴 → '나만의 공간'에서 동일한 갤러리 UI를 연다.
4. **저장 범위**: 플랫폼은 기존 Bridge로 `saveKey = 계정:게임` 를 전송하고, 양쪽은 같은 `AU.Store` namespace와 캐릭터 슬롯 키를 사용한다. `S.gallery`(tokens, unlocked, selected, attendance)와 미션 로그를 원본 저장 안에 함께 보존.
5. 독립 보기에는 캐릭터 슬롯 선택과 나가기 버튼을 제공한다. 새 캐릭터 슬롯을 열면 빈 갤러리로 시작한다.

## 범위 및 제한
- 현재의 개인 공간은 **기존 갤러리 패널에 접근하는 독립 진입 기능**. 완전히 별도 프런트엔드 앱이나 이동 가능한 공간 맵은 아니다.
- 브라우저가 지원되는 환경에서만 게임 iframe 기반 렌더링을 사용한다. 전용 경량 모바일 화면은 후속 개발.
- 플랫폼이 서버 계정과 연결되더라도 게임 원본 `AU.Store`은 브라우저 localStorage에 저장한다. 서버 간 동기화나 다른 기기 간 동일 데이터 접근은 **아직 구현되지 않았다**. 이를 '계정별 서버 보관'으로 홍보하지 말아야 한다.
- 캐릭터 저장 슬롯 1~3은 같은 계정 내 iframe 저장 namespace를 공유하지만 **캐릭터 간 갤러리 데이터는 독립**한다.
- 사진 첨부/자동 연구 수집/다른 이용자와 공유 기능은 없다. 활동 기록을 서버로 보내려면 별도 고지·동의·보안 검증 필요.

## 검증 계획
- JS 문법 및 기본 게임 회귀 테스트.
- `gallery_dual_entry.js`: 게임 단독 경로에서 ?space=1과 통상 RPG 진입 저장 공유 검증.
- `platform_gallery_entry.js`: 온앤오프 로그인 → #space-autelia → #play-autelia 전환 시 저장 공유 검증.
- 기존 프롤로그·피로도·설문·미션 보상이 훼손되지 않았는지 회귀 테스트.
