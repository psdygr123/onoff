# 아우텔리아 안정화 이후 변경 제안 (2026-11-19)

> 상태: **제안만 기록 / 게임 로직 미변경**. 현재 GitHub `main`의 게임 코드가 구현 기준입니다. 이전 회의·규칙 문서와 다른 부분을 문서에 맞추기 위해 게임을 되돌리지 않습니다.

## A. 높은 우선순위: 현실 미션과 레벨 스탯의 연동 방식
- 확인: `games/autelia/js/systems.js`의 `gateBand()`, `gateOpen()`, `pool()`, `openGate()`은 특정 레벨 구간에서 현실 미션 또는 쉼 미션으로 게이트를 열어야 자유 스탯 포인트를 사용할 수 있도록 합니다. `tests/stat_gate.js`가 이 규칙을 검증합니다.
- 설계상 긴장: 심리적 웰빙 증진 프로그램의 현실 활동은 자율성이 중요하지만, 전투 포인트를 실질적으로 묶으면 압박이 커질 수 있습니다.
- 대안: 미션은 **선택형 별도 성장 경로**로 유지하고, 전투 스탯 분배 기본 권한은 보장하되 현실 미션 완료 시 마음 성장/꾸미기/작은 편의 보상을 주는 방식 검토. 필수 게임 난이도에 영향을 주는 보상은 피합니다.
- **적용 전 확인할 결정**: 현행 게이트 유지 vs 선택형 보상 구조 전환.

## B. 마음 성장치와 설문 점수 분리
- 확인: `tests/mind_stats.js`와 `systems.js`에서 현실 미션 완료 시 PERMA 마음 스탯이 증가하며 기존 저장 이력을 복원합니다.
- 개선안: 화면에서 '마음 성장(실천 기록)'과 'K-PERMA 검사 결과'를 분리. 성장치는 완료 수만 아니라 시도·도전·의미·성찰을 바탕으로 한 **게임 보상 점수**로 확장하되, 실제 행복 수준의 객관적 측정치처럼 표시하지 않습니다.
- 가중치는 사전 확정 뒤 사용성 테스트. 만족도·의미감은 점수를 올리기 위한 정답처럼 응답하게 하지 않고 주로 미션 추천에 사용.

## C. 쉼 미션 입력 부담
- 현재 코드의 최근 커밋은 쉼 미션 후 최소 15자 소감을 요구합니다. 이 규칙은 기록의 질을 위한 장치지만 형식적 문장 입력을 유도할 수 있습니다.
- 대안: 체크형(시도 상태)+간단 자기평가(도전감/의미감)+선택형 자유 소감을 제공. 보상은 실제 시도에 연계하되 개인이 높은 만족감을 보고해야만 지급하지 않습니다.
- **기존 15자 규칙은 사용자가 승인하기 전 변경하지 않습니다.**

## D. 과거 개발 규칙 문서 정합성
- `캡스톤 개발 규칙정리본.hwpx`의 서술에는 Lv10 전직, 매일 피로도 초기화 등 초기 설계가 포함되어 있으나 현재 게임 테스트에는 Lv10 '힘의 각성', 주간 피로도 초기화가 확인됩니다.
- 설명·시트·보고서를 업데이트하여 최신 게임 수치를 문서가 반영하도록 합니다.

## E. 테스트 체계
- 기존 프롤로그 전체 실주행 테스트는 장시간 소요되며 최초 240초 제한에 도달했습니다. 통과를 확인한 것이 아닙니다.
- 빠른 회귀 테스트(게임 핵심 기능)와 장시간 실제 키 입력·프롤로그 전체 진행 검사를 **분리**하며, 장시간 검사는 단계별 진행 로그/최대 시간/스크린샷을 남깁니다.
- 기존 `tests/quest_kinds.js`는 삭제된 `q_a1_fence` 기준으로 실패합니다. 현행 퀘스트 연결 검사 `tests/current_quest_integrity.js`를 사용하는 것이 안전합니다.

## 변경 상태
- 위 A~D는 **제안만**, 실제 게임 JS/CSS/에셋/밸런스 **미수정**.
- 안정화 테스트/워크플로는 `chore/stabilization-baseline-20261119`에만 수정됨. `main` 병합 없음.
